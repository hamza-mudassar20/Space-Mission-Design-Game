# CYGNOVA — Team Roles, Release and Submission

## Proposed working roles for up to four team players
- **Mission Director** — set objective, manage cost and submit final decisions.
- **Science Lead** — choose instruments and prioritize scientific return.
- **Systems Engineer** — own mass, electrical power, protection and hardware trade-offs.
- **Flight Director** — check launch-orbit compatibility, data links and anomaly choices.

Use the in-game Mission Council checkbox to have each player approve a shared design in turn. Three of four approvals are needed to start the simulation in team mode. This is hot-seat cooperation on one screen, not networked multiplayer.

## Repository publishing (recommended static option)
1. Put `index.html`, `styles.css`, and `game.js` at the root of a public repository.
2. Enable GitHub Pages (branch `main`, root directory).
3. Open the generated public URL on a separate phone in incognito/private mode.
4. Do not assume a private Google Drive link is accessible to judges; test links.
5. Upload the 7-slide demo via a public view-only link.
6. Fill every official project field, especially NASA Data and AI use, and click **Submit for Judging**.

## Hand-off checklist
- Choose and confirm final team/project name (the provided submission screenshot currently says CYGNOVA).
- Review and retest scoring, text and data sources.
- Verify a mandatory NASA resource listed on the **specific challenge's official Resources tab** is truly integrated before Global Award eligibility assertions.
- Verify local event rules and actual time-zone deadline.
- Add human author and collaborator names, if desired, with permission and correct attribution.
- Keep all external assets licensed; don't add AI-generated NASA marks or unlicensed audio.
